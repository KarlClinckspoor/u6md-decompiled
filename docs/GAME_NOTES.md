# Compiler notes for workers

Martian Dreams was built with the same compiler as The Savage Empire (Turbo C++ 1.00), so
SE's notes apply. Notes S1-S25 are copied from `..\u6se-decompiled\docs\GAME_NOTES.md`
(addresses in them are SE's, not MD's). Notes from Martian Dreams modules go under
"Martian Dreams" at the end (workers report theirs; the coordinator adds them).

## Savage Empire

S1. secmp needs --include SRC to find se.h (secheck adds it itself).
S2. Put address comments (/*C_SSSS_OOOO*/, /*XXXX*/) only before DEFINITIONS, never before extern declarations: sesym now ignores them on externs, but keep the sources clean.
S3. With -p every function is pascal; declare externs plainly and mark only the cdecl ones cdecl (CON_printf = C_05D0_2DB9(char far *fmt, ...) is cdecl; MOUSE_SERVE C_2ABF_00A7 cdecl, no args). sesym now treats functions in -p files as pascal unless declared cdecl.
S4. A parameter declared register gets DI and a register local SI, even when the parameter is declared first (seen twice).
S5. Far data outside DGROUP (segments 2F43, 2F65): declare as `extern char far C_SSSS_OOOO[];` (secmp checks C_ names there; D_ names are taken as DS offsets).
S6. `!uchar` gives mov al/mov ah,0/or ax,ax; `uchar == 0` gives cmp byte,0. TC++ reuses a register after a store with no source trick.
S7. sedis.py's second argument is an end PARAGRAPH, not an offset (sedis.py --target game 2A81 2AC0 to see past a relocated value).
S8. _DATA found so far: main.c 00A8-01F6 (OSI_FILE's data follow at 01F6-0200), talk.c 0A06-0A36, disk.c 2A64-2B34, MOUSE 2B34-2B42, LOW 2B42-2BDA. ## Martian Dreams

M1. Tools: `tools/md/` (see SRC_M/DECOMP.md); run them with `.venv/Scripts/python` from the repository root. mdcmp needs `--include SRC_M` (and the subfolder, e.g. `--include SRC_M/OSILIB`, for assembly includes); mdcheck adds both.
M2. `-Y` (overlay support) changes no code: it only adds a COMENT record (class EAh) that TLINK /o needs. GAME.EXE's overlaid modules compile like the others.
M3. Starting points: build/port/<file> is the closest SE source with the addresses moved; build/portall.txt says how far each matches as it is.
M4. The OSI assembly segments are `WORD` aligned (OSI.INC). A module whose code segment starts with a code-segment variable (`busy db 0` in MOUSESHO, MOUSEHID) begins one byte before its first function: MOUSESHO is 0FD4:8, its entry 0FD4:9. After a module that ends on an odd address the linker inserts a pad byte; mdcheck accepts a length one larger than the code. events.asm starts at 0F2C:8 with a table of far pointers (VRETRACE is only Ah bytes).
M5. Origin's library C files (LIB/HEAP.C, LIBSIZE.C, LIBSEEK.C, MEMORY.C ...) are Turbo C++ 1.01 output. A file says so on its second line, `/* compiler: Turbo C++ 1.01 */`, and tcc.py/mdcmp/mdcheck/mdbuild then compile it with tools/tcpp101. Under 1.00, after `X = expr; f(X);` the value is reused from the register where 1.01 pushes X again from memory, and long sums come out in another order: when a library C file stalls, try 1.01. In MD `emsMapped` is read as a long (`extern long emsMapped;`). The last module before EMU086 (EMSALLOC, 1433) is followed by zeros up to the paragraph; mdcheck accepts that.
M6. From main.c's Intro (C_04FE_177E, identical): main.c is `-mm -c -O -G -y` without -d (repeated literals such as "fair.lzc" are separate). Locals take frame slots in declaration order; `register int i, key;` gives i=SI, key=DI. `if(i > 0) { A(); copy(); } else if(!B()) copy();` is cross-jumped onto one copy even with -y. `0 - i*2` gives xor dx,dx/sub dx,ax, `-(i*4)` gives neg. `abs()` is inlined (cwd/xor/sub). FADE_in (C_0CB7_0001) is pascal and returns int. A partial file mid-module: mdfunc for code, build/main-c/fixchk.py FILE PUBNAME SEG OFF DATA_BASE for its data fixups and _DATA bytes.
M7. From the rest of main.c (identical; four workers' parts merged by build/merge/merge.py): `if(f()) g();` compiled as `jne L1; jmp L2; L1:` comes from a dropped then-branch (`if(!f()) 0; else g();`). `max(1L, e)` passed straight to sqrt() uses the compiler's own temporary for fild. stdlib.h's min/max macros evaluate twice (`max(4, min(10, 20-i))`). In `a + b` with comparison values on both sides the right side is evaluated and pushed first. Calls differing only in the last argument are merged by -O into one tail (`push ax; jmp`): write if/else around separate calls. `int += unsigned` is load/add/store, `unsigned += unsigned` is `add [m],ax`. Random() results need `(unsigned)` where the original zero-extends or uses div. A double constant (18.2 = CLK_TCK) sits in _DATA among the string literals, in order of use. mdfunc and fixchk.py do not know the 8087 emulator's int 34h-3Dh (the linker's FIxRQQ fixups): they report false differences in floating-point code; mdcmp is right (build/main-d/mdfunc2.py is a fixed copy).
M8. From LZW/OSIREAD/LZC/LIBOPEN (identical): LZC is three modules (LZC.C 13A3, LZCTYPE.C 13DD, LZCLOAD.C 13F3) with LIBSIZE between: TC++ cannot put one file's functions in several code segments. Under 1.01 a long expression assigned to an int is shortened (`x/4 - 1` gives dec ax) even through casts; only `(int)(void near *)(longexpr)` keeps the long add/adc. 1.01 compares a register variable after a call (`mov di,ax / cmp di,-1`) where 1.00 reuses AX. `MK_FP(_DS, &x)` pushes ds, `(void far *)&x` pushes ss. Origin's initialised data end at DS:1CB8; 1CB8-1CC0 is padding before EMU.LIB FPINIT's paragraph-aligned _DATA.
M9. From the OSI library (identical): the OSILIB C files are mixed: SHPHIGH, PALUSED, FADESTEP need Turbo C++ 1.01, FADEIN needs 1.00, VMODE takes either: try both. 1.01 tests a register variable after a separate `X = f(); if(X == 0)` (`or di,di`); `if((X = f()) == 0)` gives `or ax,ax` under both. `_AX = i++; p[_AX] = v;` gives mov ax,si/inc si/mov bx,p/add bx,ax. An initialised global array (`= {0}`) is in _DATA: define it. FADEIN.C holds FADE_in and FADE_out (both int pascal). MEMMOVE.ASM was assembled by another assembler (TASM-style JUMPS: forward jcc padded with NOPs, far jcc as jnz $+5/jmp): the source writes those bytes with a JPAD macro. TXTCHAR starts at 0EA9:A after a pad byte; MEMMOVE at 103B:6 with its `backward` byte.
M10. The full link (MARTIAN.EXE identical): TLINK is case-insensitive, so a module function named like a library one in another case (main.c's Delay, Exit) silently replaces it and the library module is never linked: rename it. Data-only modules are found from gaps between the modules' `_DATA` ranges; their place in the link from where their relocations (FarNull pointers) sit in the .EXE relocation table. A C module that Origin compiled through the assembler (inline asm) has its fixups in code order; one compiled directly has them last to first: `#pragma inline` gives the first, and a C file of ours with inline asm can name Turbo C's order in `/* fixup order: ... */` (tools/md/tasmorder.py). `tools/md/mdsym.py apply` turns references by address into the defining module's names before a build (address names whose function now has a name are undefined at link time).
M11. GAME.EXE's FBOV segment table (target.segment_table) gives every code segment's first and last offset: it settles module boundaries, and a zero-length entry is a data-only C module's empty code segment (263D:E is OSILIB/drvnames.c; others at 0E17:4, 1649:A twice, 1FA9:2). A huge-pointer compare with 0 uses PCMP@; `or ax,[si+2]` comes from a `void far **` with arithmetic through `(char huge *)`. MASM 3.0 encodes a register-register XCHG/TEST with the first operand in the reg field (`XCHG BX,DX` gives 87 DA, `TEST SI,DI` gives 85 F7); `OR reg,imm8` (83 /1) needs db like AND.
